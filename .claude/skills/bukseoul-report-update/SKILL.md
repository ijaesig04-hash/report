# 북서울 서비스 Report 반영 · 배포

사용자: 이재식 파트장(에스원 북서울지사 서비스파트장). **항상 한국어, 쉬운 말.** 휴대폰으로만 작업하므로 답변은 짧게.

## 0. 시작 전
- 저장소에 직접 커밋·push 한다 (수동 업로드 안내 불필요). 지정된 작업 브랜치를 쓴다.
- `index.html`은 약 8MB 단일 파일. **통째로 Read 하지 말고** `grep -o` / 파이썬으로 필요한 부분만 본다.
- 고칠 때는 파이썬 문자열 치환 + **정확히 1번 일치 assert** (`assert html.count(old)==1`).

## 1. 자료별 반영 위치
| 자료 | 위치(검색어) | 탭 |
|---|---|---|
| 서비스 지표(지사·차량·개인) | `{d:"YYYY-MM-DD", br:` | cmp · veh · ppl |
| 고객체감 | `"YYYY-MM-DD":{"period"` | cs |
| 운전성향 | `var DRIVE` → snaps `"YYYY-MM-DD":[["이름",총발생,근무일,"판정"]...]` (판정은 시트 값 그대로) | drv |
| 근무표 | `DUTY` 표 + `DUTY_IMG = {"YYYY-MM":"data:image/jpeg;base64,..."}` | duty |
| 월별 평가 | eval 데이터 | eval |
| 다발보 | alm 데이터 | alm |

- 캡처를 받으면 따로 지시가 없어도 **시트의 기준 날짜**로 해당 탭에 반영.
- 반기: 상반기 = 12·1·2·3·4·5월, 하반기 = 6~11월.
- 판넬·위험예지는 앱이 구글 시트를 직접 읽으므로 반영 작업 없음.

## 2. 근무표 규칙
- 사진을 확대해 한 칸씩 옮긴 뒤, 표 아래 '주간 A / 야간 B' 일별 인원수와 **날짜마다 대조**해서 맞는지 확인.
- 코드: A 주간 · B 야간 · AJ 조석회 · D 휴무 · G 교육출장 · / 휴가(화면엔 I) · J 경조휴가 · K 공가 · P 예비군훈련.
- **표를 고치면 `DUTY_IMG`의 원본 사진도 같은 날 최신 사진으로 반드시 교체** — 사번 칸은 흰색으로 칠해서 가린 뒤 크기를 줄여 넣는다.
- 사번 등 불필요한 개인정보는 넣지 않는다.

## 3. 사진(배너 등) 교체
- 사용자가 보낸 **바로 그 사진**을 쓴다(md5로 확인). 비슷한 다른 사진으로 바꾸지 않는다. 크기만 줄인다.

## 4. 소식(NEWS) 추가 + 푸시 규칙
- `var NEWS = [` 맨 위에 한 줄 추가:
  `{id:"YYYY-MM-DD<알파벳>", date:"M/D", title:"고객체감 11/6 반영", tabs:["cs"], items:["📞 핵심 숫자 한 줄","보충 설명"]},`
- id는 그날 이미 있는 것 다음 알파벳(a, b, c…). 기존 id보다 커야 푸시가 나간다.
- 푸시는 **지표·자료 소식만**(tabs에 cmp·veh·ppl·mgt·eval·cs·alm·drv·duty). 기능·화면 변경은 `tabs:["home"]` 또는 title 앞에 `nopush:1,`.

## 5. 마무리 체크리스트 (빠짐없이)
- [ ] `<meta name="bsr-ver" content="YYYYMMDDHHMMSS">` 를 **지금 시각(KST)** 으로 갱신 — 안 하면 폰 화면이 새로고침되지 않음
- [ ] 근무표를 고쳤다면 `DUTY_IMG` 원본 사진도 교체했는지
- [ ] NEWS 맨 위 소식 추가, 푸시 대상 여부(tabs) 확인
- [ ] 데이터 형식을 바꿨다면 `.github/scripts/check.py`도 같이 수정
- [ ] 새 html 페이지를 만들었다면 `sw.js` navigate 허용 정규식에 추가
- [ ] **화면 점검 실행** (아래 6번) — 오류 0건, 반영한 탭 캡처를 눈으로 확인
- [ ] **반영 검사** `python3 tools/verify.py` 통과 — 커밋할 때 자동으로도 돌고, 실패하면 커밋이 막힘 (bsr-ver·NEWS·근무표 원본 사진·스크립트 문법·스타일 괄호)
- [ ] 커밋 메시지는 한국어로 짧게: `고객체감 11/6 반영 (발송 211, 응답 63)`

## 6. 화면 점검 (휴대폰 크기 자동 캡처)
```
node tools/screen_check.js index.html <스크래치패드>/shots
```
- 390px 휴대폰 크기로 열어 **보이는 탭을 모두 눌러** 탭별 캡처(`탭이름.png`)를 저장하고,
  자바스크립트 오류 · 화면이 옆으로 넘치는 문제를 찾아 알려준다. 오류가 있으면 종료코드 1.
- 바깥 인터넷(구글 시트 등)은 막고 파일 자체만 점검한다. 약 15초 걸림.
- '누구신가요?' 화면은 이재식으로 미리 선택해 건너뛴다. 다른 사람 화면으로 보려면 앞에 `BSR_ME=이름`.
- 캡처는 공통 머리 그림을 건너뛰고 **탭 줄부터** 찍으므로 그 탭 내용이 바로 보인다.
- 반영한 탭의 캡처는 Read로 직접 보고 숫자가 맞게 나오는지 확인. 사용자에게는 반영한 탭 캡처 1~2장만 보낸다.
- 오류가 나오면 push 전에 고친다. 원래부터 있던 오류인지는 `git stash` 후 다시 돌려 비교.

## 7. 구글 드라이브에서 자료 읽기
- 사용자가 "드라이브에 올렸어"라고 하거나 파일 이름을 말하면 캡처 대신 Google Drive 연결로 바로 읽는다
  (`search_files`로 제목 검색 → `read_file_content`). 엑셀(.xlsx)·구글 시트 모두 가능.
- 시트에서 읽은 숫자를 그대로 옮기고, 기준 날짜는 시트에 적힌 날짜를 쓴다. 캡처와 같은 반영 위치·체크리스트를 따른다.
- 판넬(`판넬부착건수_데이터`)·위험예지(`위험예지활동_데이터`) 시트는 앱이 직접 읽으므로 반영 작업 없음.
- 드라이브 파일은 읽기만 한다 (고치거나 지우지 않음).

## 8. 사용자에게 마지막 답변
- 무엇을 반영했는지(핵심 숫자) + 화면 점검 결과(정상/오류) + 푸시 발송 여부, 3~4줄로.
- 앱은 닫았다 다시 열면 최신 화면이 뜬다고 안내.
